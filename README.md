# Task Platform — Telegram Mini App + Admin

نسخة MVP موسّعة لمنصة مهام وحملات ومكافآت عربية. التقنية: FastAPI + SQLAlchemy async + PostgreSQL + aiogram + Telegram Mini App (HTML/CSS/JS) + Docker Compose.

## ما الذي يعمل في هذه النسخة

- Telegram Mini App authentication: التحقق من `initData` على الخادم باستخدام HMAC-SHA256، مع رفض التوقيع غير الصحيح والبيانات القديمة والمفاتيح المكررة والتوقيت المستقبلي غير المقبول.
- حساب واحد للمستخدم: يمكنه تنفيذ المهام وإنشاء الحملات، ولا يوجد فصل إجباري بين حساب المعلن والمنفّذ.
- لوحة إدارة على `/admin/`؛ صلاحيات الإدارة على الخادم محصورة في Telegram ID الموجود في `ADMIN_TELEGRAM_IDS` (الافتراضي `7391716280`).
- حملات إعلانات ومراجعات تجربة واختبار تطبيق ومحتوى أصلي واستطلاعات. الحملة الجديدة تدخل `pending_review` ولا تظهر للمنفذين قبل اعتماد الإدارة.
- حجز كامل ميزانية الحملة من رصيد المعلن قبل الإرسال للمراجعة، مع ضمان منفصل وتتبع المبلغ المتبقي والمصروف.
- استلام المهام وإرسال الإثباتات النصية أو الروابط/مرجع الصورة، ومنع تكرار نفس محتوى الإثبات.
- مراجعة الإثباتات، صرف المكافأة بعد القبول، إعادة فائض الميزانية بعد اكتمال المقاعد، ورفض الإثبات دون صرف.
- اعتراض واحد لكل إثبات مرفوض، ومراجعة الاعتراضات من الإدارة. قبول الاعتراض يصرف المكافأة من ضمان الحملة.
- إيقاف/استئناف/إلغاء الحملة من الإدارة. الإلغاء يعيد المتبقي للمعلن ولا يسمح به إذا كانت هناك مطالبات قيد التنفيذ أو المراجعة.
- إدارة المستخدمين، الإيقاف وإلغاء الإيقاف، مستويات الثقة (مبتدئ/موثوق/محترف/مميز)، VIP، البلاغات وسجل إجراءات الإدارة.
- دفتر قيود مالي بوحدات صحيحة `micro-USD`، ومفاتيح idempotency للعمليات المالية داخل قاعدة البيانات.
- سجل المحفظة، أرصدة متاحة/معلقة/محجوزة، وتصميم واجهة عربية RTL Glassmorphism وشريط تنقل عائم.
- بوت Telegram بسيط يفتح الـ Mini App.

## حدود مهمة — لا تستخدم أموالًا حقيقية بعد

هذه نسخة MVP برمجية وليست منصة مالية إنتاجية جاهزة. **الإيداع والسحب الآليان غير مفعّلين** لأن اسم مزود الدفع المرخّص ووثائقه وبيئة الاختبار ومفاتيحه لم تُحدد. نقاط الـ webhook والسحب ترفض التنفيذ بدلًا من ادعاء نجاح تحويل غير حقيقي. لا تضف مفاتيح أو بيانات سرية في المحادثة أو داخل ملفات الواجهة.

قبل أي أموال حقيقية يلزم اختيار مزود الدفع، تنفيذ adapter خاص به، التحقق من توقيع webhook أو استعلام server-to-server، فحص حالة العملية والمبلغ والعملة والمرجع، idempotency، التسوية، اختبارات sandbox، ومراجعة أمنية/قانونية محلية. لا تعتمد على redirect من المتصفح لتأكيد الدفع. كذلك لا توجد حاليًا خدمة تحقق تلقائي من عمر حساب Telegram أو صحة حسابات منصات التواصل، ولا نطلب كلمات مرور أو cookies أو ملفات جلسات.

التحقق من المحتوى والحملات في هذه النسخة يعتمد على مراجعة بشرية من الإدارة؛ لا تعتبر الموافقة دليلًا آليًا على أن تفاعلًا ما حقيقي أو متوافق مع سياسات كل منصة. يجب رفض أي حملة لشراء إعجابات/متابعين/مشاهدات أو تفاعل مصطنع، ومراجعة سياسات المنصة المستهدفة قبل النشر.

## التشغيل المحلي

1. انسخ `.env.example` إلى `.env`.
2. غيّر `POSTGRES_PASSWORD` في `docker-compose.yml` وكلمة المرور في `DATABASE_URL` لتطابقها. غيّر `APP_SECRET` إلى قيمة عشوائية طويلة.
3. أدخل `BOT_TOKEN` الحقيقي من BotFather، و`BOT_USERNAME`، واضبط `APP_BASE_URL` على رابط HTTPS العام بعد النشر.
4. اضبط `CORS_ORIGINS` على النطاقات الفعلية فقط، ولا تترك wildcard في الإنتاج.
5. شغّل:
   ```bash
   docker compose up --build -d
   docker compose logs -f api bot
   ```
6. تحقق من `https://your-domain/health`، ثم اربط رابط Mini App في إعدادات Telegram/BotFather.

التشغيل المحلي خارج Telegram يعرض الواجهة فقط؛ طلبات API المحمية تتطلب `initData` صحيحًا من Telegram.

## الإعدادات

- `ADMIN_TELEGRAM_IDS`: قائمة Telegram IDs مفصولة بفواصل.
- `INIT_DATA_MAX_AGE_SECONDS`: أقصى عمر مقبول لـ initData.
- `PAYMENT_PROVIDER=disabled`: الوضع الافتراضي الآمن.
- `PAYMENT_WEBHOOK_SECRET`: غير كافٍ وحده؛ يلزم تنفيذ التوقيع حسب وثائق المزود المختار.

## المال

- وحدة الحساب: USD.
- `1 USD = 1,000,000 micro-USD`.
- أقل مكافأة: `0.001 USD = 1,000 micro-USD`.
- لا تستخدم float للحسابات المالية في الخادم.
- الميزانية الممولة لا تصبح قابلة للصرف إلا من خلال قبول إثبات أو إرجاع المتبقي وفق تدفقات الخادم.
- لا توجد وسيلة إيداع/سحب فعلية حتى ربط مزود دفع مرخّص واختباره.

## قاعدة البيانات والترقيات

يتم إنشاء الجداول الجديدة عند بدء التشغيل باستخدام `create_all`. هذا مناسب لبيئة تطوير جديدة، لكنه **ليس نظام ترحيلات** ولا يعدّل أعمدة الجداول الموجودة. قبل ترقية قاعدة بيانات قائمة أو بيئة إنتاج، أضف Alembic migrations وخذ نسخة احتياطية واختبر الترحيل على نسخة staging.

## الاختبارات

بعد تثبيت متطلبات `backend/requirements.txt`:

```bash
PYTHONPATH=backend pytest -q
python -m compileall backend
```

الاختبارات المضمنة أولية ولا تغطي بعد كل حالات التزامن أو التسوية أو اختبارات اختراق؛ يجب توسيعها قبل الإنتاج.

## هيكل المشروع

- `backend/app`: API، المصادقة، الموديلات، دفتر القيود وتدفقات الحملات.
- `backend/bot`: Telegram bot.
- `miniapp`: واجهة المستخدم.
- `admin`: لوحة الإدارة.
- `tests`: اختبارات أولية.
- `nginx`: مثال reverse proxy؛ أضف TLS وإعدادات headers/rate limiting في النشر.
